# Audit, September 2026

A review of the whole app — product, flows, features, visual and accessibility — against
its own specs and against what comparable apps do. This file records what was found, what
was fixed, and what was deliberately left, so the same ground is not re-walked.

`docs/apple-design-review.md` and `docs/motion-audit.md` are the earlier, narrower reviews.
Every Tier 1 finding in both is now closed; this file supersedes neither.

## The shape of the result

The app was in better condition than the review expected. Authorization is genuinely
enforced server-side rather than hidden in the UI, the optimistic-update and rollback path
holds up under races, and the two-aggregate settlement bug `AGENTS.md` warns about is
verifiably fixed. What the audit found was not craft problems but **coverage** problems:
features that existed but nothing reached, moments that gave nothing back, and one class of
cost nobody had looked at.

## Fixed

**Getting in and staying in.**
There was no password reset anywhere, so a forgotten password locked a friend out
permanently and stranded their history. `/auth/reset` sends a six-digit code rather than a
link, because a link opened from a mail app launches the system browser rather than the
installed app. Google sign-in was added on Neon's shared credentials — no Google Cloud
project, though the consent screen names Neon rather than Tilted. The gate itself stopped
being an unbranded form and now opens on sign-up for anyone arriving from a room link,
which is the most common arrival there is.

`proxy.ts` ran the session check on every route with no timeout and no catch, so the auth
service having a bad minute took the entire app down with an error `error.tsx` could not
even catch. It now fails closed but explains itself.

**The door.**
A misheard code and a table that had gone home produced the same sentence, so nobody could
tell whether to try again. A refused knock was *deleted*, which made "the host said no" and
"the host has not looked yet" identical — the person outside went straight back to knocking
at someone who had just refused them. `join_requests.rejected_at` keeps the refusal, and
knocking again clears it, which is what keeps it "not now" rather than a ban. A request left
pending while the host moved the table to settling used to spin forever.

**Cost.**
Every phone fetched the whole game every 1.2s for an entire evening, at eight Neon round
trips each, whether or not a card had been dealt — and one of those eight returned every
buy-in of the night to the host, growing all evening. The meter on a free plan is not
queries but *wakefulness*, and nothing could scale to zero while a question arrived twice a
second. Phones now compare a one-statement fingerprint and read in full only when it
changes, backing off to 10s while the table is quiet. See the latency invariant in
`AGENTS.md`.

The service worker handled push only, so losing the network replaced the ledger with the
browser's error page. It now serves an offline shell — and caches no HTML at all, because
every page here is rendered for a signed-in person.

**The moment somebody finishes.**
Settling replaced a player's total with a badge, so the one moment a player most wants a
number was the moment the screen took it away. `YourResultCard` puts the night back where
the rebuy button was.

**The night afterwards.**
The summary was shareable only as an image. The image stays, but an image cannot be searched
three weeks later, so there is a text twin — with every amount fenced in directional
isolates and transfers written as sentences. Both are in `src/lib/summary-text.ts`, with the
bidi reasoning recorded there.

**What the group is.**
History listed nights and opened one; nothing said how the group was doing. `/group` adds
attendance, locations, and head-to-head against the viewer. Push fired for exactly one event
and now covers a knock, the table being counted, and the night closing.

**Craft.**
The dropdown menu's rows were 28px — the worst target in the app, on the menu holding
"delete rebuy". The share image's felt could not carry text at any opacity (white measured
2.54:1 on it). The pot and feed announce politely. Two controls a thumb aims at all evening
were set below every step in the type scale.

## Deliberately not done

- **Seating (v2 item 10)** — retired by the product owner. See `docs/v2-plan.md` M5.
- **An all-time money leaderboard** — `docs/poker-night-spec.md:137` rules it out because
  cumulative totals permanently disadvantage whoever joined last, and that reasoning still
  holds. Head-to-head is allowed because it counts only nights both people played, so it
  starts empty for both sides at once. `/group` shows attendance and single-night figures,
  never a per-person running total.
- **Accountless guest join** — the dominant pattern in comparable apps (Mainpot, Tricount,
  Splid all allow it) and a considered rejection here, not an oversight. It would cost the
  server-side authorization rule.
- **Wrapping `env(safe-area-inset-*)` in `max()`** — raised by the review, then measured and
  dropped. All fourteen call sites are additive (`calc(0.75rem + env(...))`), so a transient
  zero degrades to the base padding. `max()` would change nothing.
- **Shared non-poker expenses** (food, drinks) — the most-requested adjacent feature in
  comparable Israeli apps. Real scope, not absorbed silently. Would need a decision about
  whether this stays a poker ledger.

## Second pass, September 2026 — the UI/UX review

A whole-app pass against mobile, RTL and WCAG 2.2 practice, and against what comparable
apps do. Research covered poker ledgers (Mainpot, Tilt, Pokertally) and the split-expense
apps that solve the same settlement problem (Splitwise, Tricount, Settle Up, Splid).

### What it found that was actually broken

**Six players broke the table.** `railPoints` spaced seats by equal arc length while
`railTier` handed back a width from an independent ladder, and nothing made the two
agree. From six players up, adjacent seat buttons genuinely overlapped in the DOM -- both
at `z-20`, so a tap in the overlap resolved to whichever painted later rather than the one
under the thumb. On the ordinary night, where the host enters everyone else's rebuys from
one phone, that credited the wrong player's money. `src/lib/seat-layout.test.ts` now
re-derives the gaps from the geometry and fails if any tier outgrows its room.

**A failed roster fetch bricked "open a table", silently.** `peopleRetryCount` was
destructured with no setter, so the retry was dead code and its effect had a dependency
that could never change; `disabledReason` returned `null` for exactly the case where the
button was disabled. On a failed fetch the host reached the last step, found the button
dead, and got no explanation -- and an installed PWA has no pull-to-refresh, so the only
way out was force-quitting.

**Rose meant two things.** `brand-*` maps to `--red-400`, the money-down ink, and was also
the app's general accent across eleven roles -- including the winner's crown, and the
focus border on every text field in the app. The app already disagreed with itself: the
best-hand crown and the share card used amber, the live table's crown used violet, and
`globals.css` had been reserving `--amber-400` "winner, countdown. Nothing else." for a
token used in exactly one place. Rose is now money and its destructive cousin only.

**Smaller, and real:** `extendTime` had no in-flight guard, so two taps added an hour;
guests got a press animation and `aria-pressed` on seats they could never act on, because
the host gate was inside the callback rather than on the prop; the player-actions dialog
had no exit but an undiscoverable backdrop tap; the delete-player dialog named the person
but not the money it was about to erase; "היסטוריית השולחן" claimed to be the night's
history while showing the last twelve rows of it.

### Also fixed

Route-level loading states (there were none anywhere, on `force-dynamic` routes awaiting a
Neon compute that may be asleep). A foreground refetch on home, since an installed PWA has
no pull-to-refresh. `touch-action: manipulation`, which appeared nowhere, on controls built
to be tapped twenty times in a row. Hit-area compensation on the below-floor button and
toggle sizes, which `switch.tsx` and `checkbox.tsx` already had and `button.tsx` did not.
A second channel on the tab bar's active state. The drawer handle's contrast (open item 6
below). A consequence confirmation before mismatch resolution assigns the counting gap to
one named person. A typed confirmation on purging a night, which destroys other people's
history and previously needed one tap while deleting your own account needed a typed word.
`/history` pagination. `/group`'s empty state, which told first-time visitors that a search
they never typed had failed. The money fields still on `type="number"`.

### Added

**Rematch** — `/game/new?from=<gameId>`, reached from home. This group plays the same
people most weeks, and the roster step was the one nobody needed to repeat. It pre-fills
and does not commit; people who have left the group since are dropped rather than seated.

### Considered and rejected

- **A host approval gate on player-submitted rebuys.** Mainpot and Tilt both have it, and
  both converged on it for the same reason: anyone can claim anything. That is not a
  problem here -- the signed-in Person writes only their own row, enforced server-side --
  so it would add a step to the most frequent action of the night to solve something
  already solved structurally.
- **A live leaderboard during play.** The social payoff of the genre (Golf GameBook), and
  not honestly computable in a poker ledger: until someone counts chips you know what
  people put in, not what they hold. The only truthful live ranking is who is in deepest,
  which is a different feature and a product decision.
- **Gating "host a game".** Both paid competitors put their meter exactly there. It is the
  one asymmetry that would turn a friends' ledger into a money conversation.

## Still open

Ranked by what it costs.

1. **Route-layer tests.** 33 of 36 route handlers have none, and there are no component
   tests at all — which is why a completely unreachable feature (seating) could ship. The
   pure `lib` functions are well covered; `live-queries.ts`, `history-queries.ts` and
   `join-request-queries.ts` are not.
2. **The type scale.** Roughly ninety raw `text-xs` / `text-sm` / `font-bold` usages remain
   where `docs/design-system.md` says only the eight `.t-*` steps may appear. The
   below-scale ones are fixed; the rest are a mechanical pass that needs visual checking,
   because `text-sm` and `.t-label` share a size but not a line-height.
3. **Mark-as-paid has no optimistic lock.** Two phones toggling one transfer last-write-wins
   with nothing surfaced.
4. **Mismatch resolution can delete transfer rows** whose `paid_at` does not survive the
   pair no longer existing.
5. **Chip-count debounce is not flushed on unmount**, so a phone locking inside the 350ms
   window can drop the last tap.
6. ~~**The drawer handle** is 2.18:1 against its sheet~~ — fixed in the September UI/UX
   pass.
7. **The arc cannot hold the table the app allows.** Nine opponents leaves 27px of rail
   per seat on a 390px phone, and no choice of width fixes it: ten 44px targets need more
   span than the screen has. Seats no longer overlap at any count, but past six opponents
   the button drops below the 48px floor. Above seven players this arc needs to stop being
   an arc -- a product decision, not a geometry one.
8. **The ten-player cap is enforced in `createGame` only.** Neither `approveJoinRequest`
   nor `addPlayerToGame` checks it, so a table can grow past ten through the door or by
   hand -- past the number of avatar keys that exist, which is where the cap came from.
9. **`AmountInput` has no minus.** The hand recorder's per-player result is signed, and
   `inputMode="decimal"` shows a pad without one. Pre-existing; the fix is a +/- toggle
   rather than a keyboard change.
